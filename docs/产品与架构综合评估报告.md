# InfinityNoteX 产品与架构综合评估报告

## 1. 项目概览

- 形态：跨平台 Electron 桌面应用，渲染层 React + TypeScript + Vite，主进程集中在 `electron` 目录。
- 核心能力：本地优先的笔记/便签、浮窗/药丸快速记录、AI 对话与工作台（OpenAI 兼容）、附件管理（自定义 attachment:// 协议）、WebDAV 文件级同步、知识库（向量存储/Embedding 配置）、自动更新与日志体系。
- 目标用户：需要多端（至少多设备）一致的本地知识管理与轻量协同的个人/小团队用户，对隐私、离线可用性和自建同步通道有需求。

## 2. 产品视角评估

### 2.1 价值与定位

- 本地优先 + 自建同步（WebDAV），降低上云门槛；兼顾隐私与可迁移性。
- AI 融合：对话、工作台与后续 RAG 能力，为知识创作/检索提速。
- 多窗口形态：主窗 + 浮窗 + 药丸，覆盖长文编辑与轻量采集。

### 2.2 体验亮点

- 首次启动引导（WelcomeScreen）与存储路径选择，降低冷启动成本。
- 附件协议与浏览器卡片，扩展内容形态与外部资源入口。
- 自动更新组件（前端 UpdateNotifier + electron-updater）降低发布摩擦。

### 2.3 主要短板与机会

- **同步心智**：目前仅 WebDAV，缺少冲突可视化、变更日志、失败重试/定时策略与带宽提示。
- **知识库与 AI**：知识库用途、与普通笔记/对话的差异未明确；缺少示例库与“一键导入+嵌入测试”向导。
- **快速捕获链路**：浮窗/药丸缺少全局快捷键、截图/粘贴入口、模板化新建；跨应用采集需要强化。
- **安全与信任**：AI/WebDAV 凭据存储在配置文件；附件协议缺少类型/大小限制；未显式提供数据加密/敏感提示。
- **健康可视化**：无统一的健康面板（同步状态、存储容量、索引健康、日志入口）。
- **生态互通**：导入/导出（Markdown/HTML/OPML/JSON）与迁移路径未包装成用户向导。

### 2.4 产品优先级建议（建议顺序）

1. 同步体验：预览/冲突列表、失败重试与定时同步、进度/带宽提示。
2. 知识库可用性：示例库 + 一键导入 + 嵌入测试；AI 调用知识库的显式入口与提示文案。
3. 快速捕获：全局快捷键、截图/粘贴直存、模板化新建；浮窗/药丸的无干扰模式。
4. 安全与信任：凭据加密/系统钥匙串、附件类型/大小白名单、隐私提示；自动更新的渠道选择与回滚预案。
5. 生态与迁移：导入/导出向导，常见平台/云盘的迁移脚本与说明。

## 3. 架构视角评估

### 3.1 分层与模块

- **主进程**：窗口/多窗口管理、自定义协议、自动更新、日志、存储聚合、AI/知识库/同步 IPC（核心入口：`electron/main.ts`）。
- **Preload**：分门别类暴露 IPC API（窗口、存储、AI、同步、附件、知识库等），集中在 `electron/preload.ts`。
- **渲染层**：React + Zustand，功能通过 feature registry 装配；三段式布局（Sidebar + List + Editor），支持浮窗/药丸路由（`src/App.tsx`）。
- **存储层**：`StorageManager` 聚合 folders/notes/ai/trash/attachments/browserCards + IndexCache + DeviceManager，支持路径迁移、崩溃恢复、迁移框架与索引重建。
- **同步层**：WebDAV 客户端 + SyncEngine，支持预览/执行与冲突策略（默认 newest）。
- **AI 层**：OpenAI 兼容适配器（流式/非流式 + 连接测试），后续可扩展其它 Provider。
- **知识库**：向量存储（sqlite-vec）与嵌入配置接口，预留本地检索与 RAG 能力。

### 3.2 架构优势

- 职责分明，IPC 命名清晰；存储抽象集中，便于扩展子模块与更换存储路径。
- 自定义协议 attachment:// 解耦附件路径，利于迁移与安全控制。
- 适配器模式覆盖 AI/同步/知识库，易于增加 Provider。
- 启动期包含崩溃恢复、索引重建、迁移框架，具备基础自愈能力。

### 3.3 风险与改进点

- **一致性/迁移**：迁移框架未实现具体迁移；索引重建全量扫描在大数据量下需优化，建议增量索引与哈希校验。
- **并发与写安全**：多窗口与同步同时写文件需明确写锁/原子写策略，尤其是附件与大文本。
- **同步冲突**：仅 newest 策略，缺少三方合并或内容级 diff；附件/富文本冲突需预案。
- **安全**：凭据明文存储；附件协议缺少类型/大小限制；渲染层日志可能泄露敏感信息。
- **观察性**：日志已分级，但缺少指标（同步耗时/失败率、索引重建耗时、附件清理统计）和面向用户的诊断面板。
- **性能**：TipTap 大文档、附件大图处理需压测；列表虚拟化与懒加载可进一步优化。
- **测试与交付**：Vitest 在位但需补充关键路径契约测试；CI 未串联 build/lint/test；自动更新/签名链路需验证。

### 3.4 技术优先级建议

1. 数据与同步安全：写锁/原子化策略，冲突解决（预览/三方合并），配置加密。
2. 观察性与自愈：健康检查面板，指标埋点，失败重试/告警，索引与存储一致性巡检。
3. 知识库与 AI：检索/调用链路清晰化，向量索引生命周期管理，流式错误处理完善。
4. 性能：索引增量化、附件清理策略、列表虚拟化和大文档优化。
5. 质量与发布：关键路径测试、CI 串联 build-all/lint/test，自动更新签名与回滚预案。

## 4. 近期行动清单（建议执行序）

1. 设计并实现“同步与数据健康”面板：容量/索引状态、同步进度与冲突列表、失败重试入口。
2. 为 WebDAV 同步增加定时/手动触发策略、失败重试、冲突可视化（含附件处理），并记录操作日志。
3. 知识库上手包：示例库 + 一键导入 + 嵌入测试向导；AI 回答中显式标识知识库命中与引用片段。
4. 全局快捷键与快速采集：浮窗/药丸快捷键、截图/粘贴直存、模板化新建；无干扰模式。
5. 安全增强：凭据加密/钥匙串支持，attachment:// 类型/大小白名单，敏感日志脱敏；自动更新渠道与回滚开关。
6. 测试与 CI：补充存储/同步/AI 契约测试，接入 CI（build-all/lint/test），验证签名与更新链路。
