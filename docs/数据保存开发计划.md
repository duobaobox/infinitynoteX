# 数据持久化与数据管理开发计划（v1）

本文整理并优化当前关于“真实数据落盘”的需求，形成第一版可实施的开发计划。目标是建立从应用首次启动到设置页配置、创建文件夹/便签、数据迁移与备份的一条闭环链路，并与现有 Electron + React + Ant Design 技术栈良好集成。

## 背景与目标

- 背景：目前应用中的便签与文件夹为“假数据”。
- 目标：实现本地文件系统为基础的真实数据持久化；首次启动无需选择路径即可使用；内置一个不可删除的默认文件夹；在“设置-数据管理”中可配置/迁移存储路径；全流程可用、可恢复、可回滚。
- 范围（v1）：文件夹与便签的创建/读取/更新/删除（CRUD），存储路径管理与迁移，自动保存与基础备份；图片/附件与同步等高阶能力暂列后续版本。

## 术语约定

- 文件夹：便签的归属分组，包含排序、创建时间等元信息。
- 便签：富文本（采用 TipTap JSON）与基础元信息的组合数据实体。
- 存储根目录（storageRoot）：应用用于存储数据的根目录。
- 系统默认文件夹：首次初始化时创建，不可删除（v1 不可重命名）。

## 需求梳理

### 显式需求（来自用户）

1. 首次打开软件：主页可直接使用，无需先指定文件存储路径。
2. 支持创建“文件夹”，在文件夹下创建“便签”。
3. 系统默认内置一个“默认文件夹”，不可删除。
4. 设置中新增“数据管理”Tab，用于配置存储路径。
5. 全流程闭环：包含初始化、正常使用、变更路径、迁移与恢复。

### 补充与约束（为落地补全）

- 默认存储路径：采用 Electron `app.getPath('userData')` 下的专用子目录（如 `data-v1`）。
- 首次启动：自动在默认路径完成初始化，不弹窗打断流程。
- 更改存储路径：在“数据管理”中可选择新路径，并支持一键迁移旧数据；迁移失败可回滚。
- 数据结构：采用“文件系统 + JSON 索引/文档”的形式，避免引入数据库依赖，降低首版复杂度。
- 并发与一致性：单实例写入，采用原子写与写入前备份策略，避免数据损坏。
- 备份：最小可用备份（最近一次成功保存的快照），支持手动导出全部数据目录。
- 跨平台：设计路径与读写逻辑兼容 macOS / Windows / Linux（按 Electron 标准路径）。

### 非功能需求

- 性能：列表/索引文件常驻缓存，避免大目录遍历；写入采用节流（例如 500ms-1000ms）。
- 稳定性：崩溃恢复、安全落盘（先写临时文件，完成后 rename）。
- 可维护性：明确的数据版本号，便于未来迁移（`schemaVersion`）。

## 数据模型与目录结构

### 概念模型

- Folder

  - id: string（使用 nanoid 或 UUID；系统默认为 `default`）
  - name: string
  - createdAt: number
  - updatedAt: number
  - order: number（用于侧边栏排序）
  - system: boolean（系统默认文件夹为 true，不可删除；v1 不可重命名）

- Note
  - id: string
  - folderId: string
  - title: string
  - content: TipTap JSON（或未来支持 Markdown）
  - excerpt: string（用于列表预览，渲染时生成并存放在索引中）
  - pinned: boolean
  - tags: string[]
  - createdAt: number
  - updatedAt: number

### 本地目录布局（v1）

```
{storageRoot}/
	meta.json                # 存储级别元信息：schemaVersion、storageId、createdAt
	folders.json             # 所有文件夹的数组，含系统默认标志与排序
	notes.index.json         # 便签的轻量索引（id、folderId、title、excerpt、updatedAt、pinned）
	notes/                   # 便签正文分开存储，便于增量加载
		{noteId}.json          # 单条便签完整内容（含 content JSON）
	backups/                 # 自动/手动备份目录（可选，v1 仅保留最近一份）
	temp/                    # 原子写临时目录
```

### 文件示例

- `meta.json`

```json
{
  "schemaVersion": 1,
  "storageId": "a1b2c3d4",
  "createdAt": 1730515200000
}
```

- `folders.json`

```json
[
  {
    "id": "default",
    "name": "默认文件夹",
    "system": true,
    "createdAt": 1730515200000,
    "updatedAt": 1730515200000,
    "order": 0
  }
]
```

- `notes.index.json`

```json
[
  {
    "id": "n1",
    "folderId": "default",
    "title": "示例便签",
    "excerpt": "这是预览片段...",
    "updatedAt": 1730515200000,
    "pinned": false
  }
]
```

- `notes/{id}.json`

```json
{
  "id": "n1",
  "folderId": "default",
  "title": "示例便签",
  "content": {
    "type": "doc",
    "content": [
      { "type": "paragraph", "content": [{ "type": "text", "text": "Hello" }] }
    ]
  },
  "tags": [],
  "pinned": false,
  "createdAt": 1730515200000,
  "updatedAt": 1730515200000
}
```

## 存储路径策略与迁移

### 默认与首次启动

- 默认路径：`app.getPath('userData')/data-v1`。
- 首次启动：若目录不存在则初始化（写入 `meta.json`、`folders.json`、空的 `notes.index.json`、并创建 `notes/`）。
- 不弹出路径选择，用户可立即创建“文件夹”与“便签”。

### 设置页“数据管理”Tab（AntD）

- 展示当前存储路径与基础统计（文件夹数、便签数、数据占用、最近备份时间）。
- 操作：
  - 选择新路径（系统文件对话框）。
  - 迁移数据到新路径（带进度与日志输出）。
  - 打开当前数据目录（打开 Finder/Explorer）。
  - 导出全部数据（打包为 zip，v1 可先导出目录）。

### 更改存储路径的迁移流程

1. 选择新路径 -> 校验（可写、空间足够、目录为空或仅包含本应用签名）。
2. 暂停写入 -> 创建备份快照 -> 拷贝所有文件到新路径（保留权限、时间戳）。
3. 校验新路径完整性（校验文件数量、meta 与索引可读性）。
4. 原子切换：更新应用内“当前路径”指针并持久化设置。
5. 清理与回滚：若任一步骤失败，回退到旧路径并提示错误详情。

### 错误与边界

- 默认文件夹不可删除；若删除请求发起，返回业务错误码 `E_FOLDER_SYSTEM`。
- 删除文件夹时，需选择“移动便签到默认文件夹”或“同时删除便签”（v1 采用强约束：仅允许移动到默认文件夹）。
- 写入失败（磁盘满、权限问题）返回 `E_IO_WRITE`；读取失败返回 `E_IO_READ`；路径非法返回 `E_PATH_INVALID`。

## 进程间接口契约（IPC）

通过 `preload.ts` 暴露 `window.storage` 命名空间，仅暴露白名单 API（contextIsolation 开启）。

### API 列表（函数签名）

- 路径与健康

  - `getDefaultPath(): Promise<string>`
  - `getCurrentPath(): Promise<string>`
  - `setStoragePath(nextPath: string, options?: { migrate: boolean }): Promise<void>`
  - `healthCheck(): Promise<{ ok: boolean; details?: string }>`
  - `openInFinder(): Promise<void>`

- 文件夹

  - `listFolders(): Promise<Folder[]>`
  - `createFolder(name: string): Promise<Folder>`
  - `renameFolder(id: string, name: string): Promise<Folder>`
  - `deleteFolder(id: string): Promise<void>` // 系统默认文件夹触发 `E_FOLDER_SYSTEM`

- 便签

  - `listNotes(folderId?: string): Promise<NoteIndex[]>`
  - `createNote(folderId: string, payload?: { title?: string; content?: any }): Promise<Note>`
  - `getNote(id: string): Promise<Note>`
  - `updateNote(id: string, patch: Partial<Note>): Promise<Note>`
  - `deleteNote(id: string): Promise<void>`

- 搜索（v1 可选，简单全文包含）
  - `search(query: string): Promise<NoteIndex[]>`

### 事件与通知

- `onStoragePathChanged(listener: (path: string) => void)`
- `onIndexUpdated(listener: () => void)`（便签/文件夹变更后触发）

### 错误码（建议）

- `E_FOLDER_SYSTEM`：试图删除系统默认文件夹。
- `E_IO_READ` / `E_IO_WRITE`：文件读写错误。
- `E_PATH_INVALID`：路径不可用或权限不足。
- `E_MIGRATE_FAIL`：迁移失败（包含详细原因）。

## 前端 UI 交互（Ant Design）

- 首页（无需路径选择）：

  - 侧边栏（`Sidebar.tsx`）：渲染 `listFolders()`；提供“新建文件夹”。
  - 列表（`ListPanel.tsx`）：渲染 `listNotes(folderId)`，支持置顶、搜索。
  - 编辑区（`EditorPanel.tsx` + `TipTapEditor`）：自动保存（节流 800ms），保存成功后更新 `notes.index.json`。

- 系统默认文件夹规则：

  - UI 上隐藏删除按钮；尝试删除时弹出受限提示。

- 设置页（`SettingsModal/SettingsModal.tsx`）：新增“数据管理”Tab：

  - 当前路径展示 + 复制按钮。
  - “选择新路径”按钮（`dialog.showOpenDialog`）。
  - “迁移到新路径”复选项 + 执行按钮 + 进度条。
  - “打开数据目录”“导出数据”操作入口。

- 空态与引导：
  - 首次无文件夹/便签时，展示空态卡片与引导按钮（AntD Empty + Button）。

## 自动保存与一致性

- 编辑器变更采用节流写入（800ms）；连续输入不频繁落盘。
- 写入流程：先写入 `temp/{file}.tmp` -> 成功后 `rename` 覆盖目标文件，实现原子替换。
- 更新顺序：先写正文，再更新 `notes.index.json`，避免索引指向脏数据。
- 崩溃恢复：若存在 `.tmp` 文件，启动时尝试恢复并记录到日志。

## 权限、安全与沙箱

- 仅通过 `preload` 暴露白名单方法；禁用 `remote`；`contextIsolation: true`。
- 所有路径均标准化并限制在存储根目录下（除迁移/选择路径过程外）。

## 日志与诊断

- 写入关键节点日志：初始化、迁移、备份、失败原因（可写入 `{storageRoot}/logs/app.log`，或先使用 `console` 加载到调试面板）。

## 测试计划与验收标准

- 单元测试（主进程文件读写）：

  - 初始化生成目录与基础文件。
  - 创建/更新/删除文件夹与便签。
  - 系统默认文件夹删除受限。

- 集成测试（渲染层）：

  - 首次启动即可创建便签并成功落盘。
  - 设置页选择新路径并成功迁移。

- 验收标准（v1 Done 定义）：
  - 首次打开无需选择路径即可创建文件夹/便签并落盘；默认文件夹不可删除；设置页能查看/更改路径并完成迁移；应用重启后数据完整无误。

## 实施计划与任务拆解

### 里程碑

- M1 基础落盘与默认文件夹（2-3 天）

  - main/preload 存储 API 框架与默认路径初始化
  - `folders.json`、`notes.index.json`、`notes/` 读写
  - UI 侧边栏/列表/编辑器对接 CRUD

- M2 设置页“数据管理”与迁移（2 天）

  - AntD Tab 与统计展示
  - 路径选择与迁移流程（含回滚）

- M3 稳定性与备份（1-2 天）
  - 原子写与崩溃恢复
  - 最近一次快照备份与导出

### 任务清单（与代码位置）

1. 主进程（`electron/main.ts`）
   - 实现文件系统存储模块（初始化/读写/迁移）。
   - 定义 IPC 通道与错误码。
2. 预加载（`electron/preload.ts`）
   - 通过 `contextBridge` 暴露 `window.storage` API。
3. 渲染层
   - 侧边栏（`src/components/Sidebar.tsx`）：文件夹 CRUD。
   - 列表（`src/components/ListPanel.tsx`）：便签列表、搜索、置顶。
   - 编辑器（`src/components/EditorPanel.tsx` + `TipTapEditor`）：自动保存。
   - 设置（`src/components/SettingsModal/SettingsModal.tsx`）：新增“数据管理”Tab 与交互。
4. 公共模块
   - 定义前端类型（`src/services/types.ts` 或复用现有 `TipTapEditor/types.ts`）。
   - 节流、防抖与错误提示（AntD message/modal）。

## 未来扩展（v2+）

- 图片/附件管理：`assets/` 目录与内容引用，清理未引用资源。
- 全文搜索与索引优化（如建立倒排索引）。

附：小契约（Contract）

- 输入与输出
  - 所有 IPC 返回 Promise；错误通过 reject 并带错误码。
  - 便签正文以 TipTap JSON 存储；索引中仅放轻量字段。
- 成功标准
  - 创建/编辑/删除操作在 1 秒内可见；重启后持久存在。
- 主要边界用例
  - 目标路径只读/空间不足/已有残留数据；编辑时断电；重复创建文件夹名；删除存在便签的文件夹。
