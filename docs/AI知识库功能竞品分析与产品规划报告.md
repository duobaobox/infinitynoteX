## 💡 产品思路对比

### Notion AI 的产品哲学

```mermaid
graph LR
    subgraph "Notion AI 核心理念"
        A[工作区即知识库] --> B[AI 无处不在]
        B --> C[减少切换成本]
        C --> D[提升团队效率]
    end

    style A fill:#f9f,stroke:#333
    style D fill:#9ff,stroke:#333
```

**关键洞察**:

1. **集成至上** - AI 不是独立功能，而是融入每个交互点
2. **多源聚合** - 将分散的知识（Slack、Google Drive、GitHub）统一检索
3. **信任与透明** - 来源引用建立用户对 AI 输出的信任
4. **降低门槛** - 问答式交互，无需学习复杂操作

**商业逻辑**:

- AI 作为付费增值功能（$10/用户/月）
- 强化团队协作价值，提升粘性
- 数据锁定：越多内容存储在 Notion，切换成本越高

---

### Affine AI 的产品哲学

```mermaid
graph LR
    subgraph "Affine AI 核心理念"
        A[本地优先] --> B[视觉化思维]
        B --> C[AI 赋能创作]
        C --> D[开源透明]
    end

    style A fill:#bfb,stroke:#333
    style D fill:#fbf,stroke:#333
```

**关键洞察**:

1. **视觉化优先** - 白板与文档融合，适合创意工作者
2. **隐私至上** - 本地存储、自托管选项，满足敏感数据需求
3. **开源生态** - 社区驱动创新，避免供应商锁定
4. **多模态 AI** - 不仅理解文字，还能理解图像和布局

**商业逻辑**:

- 开源核心 + 付费云服务（团队版）
- 面向开发者和技术团队
- 差异化定位：Notion 的本地优先替代品

## 🛠️ 功能实现规划

### Phase 1: 知识问答基础（MVP）

**目标**: 2-3 周内实现基础知识问答

| 功能           | 优先级 | 实现方式                   | 工作量 |
| -------------- | ------ | -------------------------- | ------ |
| 笔记向量化索引 | P0     | sqlite-vec + Embedding API | 3天    |
| 基础问答       | P0     | RAG + 现有 OpenAI Adapter  | 3天    |
| 来源引用       | P0     | 检索结果关联原笔记         | 1天    |
| 增量索引       | P1     | 笔记变更监听器             | 2天    |
| UI 集成        | P1     | AI 面板增加"知识问答"模式  | 2天    |

**技术架构**:

```mermaid
sequenceDiagram
    participant U as 用户
    participant AI as AI 面板
    participant RAG as RAG 引擎
    participant VDB as 向量数据库
    participant LLM as LLM API

    U->>AI: 输入问题
    AI->>RAG: 发起查询
    RAG->>VDB: 语义检索
    VDB-->>RAG: 返回相关笔记片段
    RAG->>LLM: 构建 Prompt + 上下文
    LLM-->>RAG: 生成回答
    RAG-->>AI: 回答 + 来源引用
    AI-->>U: 展示结果
```

## ✨ 亮点功能提案

## ⚠️ 风险与挑战

### 技术风险

| 风险               | 等级 | 缓解措施                   |
| ------------------ | ---- | -------------------------- |
| sqlite-vec 集成    | 中   | 预研 Electron 原生模块加载 |
| 大量笔记索引性能   | 中   | 后台增量索引、批量处理     |
| Embedding API 成本 | 低   | 本地缓存、仅索引变更部分   |
| 本地模型体积       | 中   | 按需下载、压缩模型         |

### 产品风险

| 风险           | 等级 | 缓解措施                |
| -------------- | ---- | ----------------------- |
| 用户预期过高   | 中   | 明确 MVP 边界，快速迭代 |
| 与编辑体验冲突 | 低   | AI 功能作为可选模块     |
| 隐私担忧       | 低   | 透明说明数据处理方式    |

## 📝 总结与建议

### 立即行动

1. **技术验证**: 完成 sqlite-vec 在 Electron 中的集成验证
2. **原型设计**: 设计知识问答的交互流程
3. **用户访谈**: 收集目标用户对知识库功能的需求反馈

### 核心原则

1. **隐私第一**: 所有数据处理都在本地完成
2. **渐进增强**: 从简单问答开始，逐步增加复杂功能
3. **体验一致**: AI 功能与现有编辑器体验无缝融合
4. **灵活配置**: 支持用户自定义 LLM 和嵌入模型

### 成功指标

| 指标         | Phase 1 目标 | 长期目标    |
| ------------ | ------------ | ----------- |
| 问答响应时间 | < 5秒        | < 2秒       |
| 回答相关性   | > 70%        | > 90%       |
| 索引覆盖率   | 100% 笔记    | 100% + 附件 |
| 用户满意度   | > 60%        | > 85%       |
