# 数据同步使用手册

## 概述

InfinityNoteX 采用 **Dropbox 风格的双向同步**，通过 WebDAV 协议实现多设备数据同步。

### 核心特点

- ✅ **双向同步**：本地和云端的修改都会互相同步
- ✅ **增量同步**：只传输变化的文件，节省流量
- ✅ **冲突处理**：自动或手动解决多设备冲突
- ✅ **删除传播**：删除操作会同步到其他设备

---

## 快速开始

### 1. 配置 WebDAV

进入 **设置 → 数据同步 → WebDAV**：

| 字段       | 说明               | 示例                             |
| ---------- | ------------------ | -------------------------------- |
| 服务器地址 | WebDAV 服务器 URL  | `https://dav.jianguoyun.com/dav` |
| 用户名     | 登录账号           | `your@email.com`                 |
| 密码       | 登录密码或应用密码 | 坚果云需使用应用密码             |
| 远程路径   | 数据存储目录       | `/InfinityNoteX`                 |

### 2. 测试连接

点击 **测试连接** 按钮，确认配置正确。

### 3. 首次同步

点击 **立即同步**：

- 本地数据会上传到云端
- 云端已有数据会下载到本地

## 同步机制详解

### 三方比较算法

同步时会比较三个状态：

1. **本地当前状态**：本地文件的当前内容
2. **上次同步状态**：上次同步时的记录
3. **远程当前状态**：云端文件的当前内容

### 同步决策矩阵 - 双设备案例讲解

> 假设你有 **电脑** 和 **iPad** 两台设备，都装了 InfinityNoteX

#### **规则 1️⃣ ：本地有(无变化) + 云端有(无变化) + 上次同步有**

**含义**：这个便签三个地方都一样，没人动过

```
上次同步：便签内容是 "购物清单" (md5: abc123)
         ↓
电脑上现在：还是 "购物清单" (md5: abc123)  ← 没改
         ↓
云端现在：还是 "购物清单" (md5: abc123)   ← 没改
         ↓
iPad上现在：还是 "购物清单" (md5: abc123)  ← 没改

👉 决策：⏭️ 跳过（什么都不用做）
```

---

#### **规则 2️⃣：本地有(已修改) + 云端有(无变化) + 上次同步有**

**含义**：只有你这个设备改过，别的设备没改

```
上次同步：便签内容是 "购物清单"
         ↓
你在电脑上改成：
  "购物清单
   - 牛奶
   - 面包"

云端还是：原来的 "购物清单" (没人改)

iPad上：也是原来的 "购物清单" (没收到电脑的改动)

👉 决策：⬆️ 上传本地版本
   电脑的新内容上传到云端 → iPad 下次同步就能看到最新版本
```

---

#### **规则 3️⃣：本地有(无变化) + 云端有(已修改) + 上次同步有**

**含义**：你这个设备没改，但云端改了（另一设备改的）

```
上次同步：便签内容是 "购物清单"
         ↓
你的电脑：没动过，还是 "购物清单"

云端现在：
  "购物清单
   - 牛奶
   - 面包"
  (iPad 在 2 小时前改的并上传了)

👉 决策：⬇️ 下载云端版本
   把 iPad 的最新版本下载到电脑上
   这样两台设备就同步了
```

---

#### **规则 4️⃣：本地有(已修改) + 云端有(已修改) + 上次同步有**

**含义**：你在电脑改，别人也在 iPad 改，两个不同的版本

```
上次同步：便签内容是 "购物清单"
         ↓
你在电脑改成：
  "购物清单
   - 牛奶
   - 面包
   - 鸡蛋"

同时，你的朋友在 iPad 改成：
  "购物清单
   - 牛奶
   - 酸奶
   - 饼干"

这两个版本都上传到了云端
当电脑或 iPad 同步时就会检测到：
「咦，两个不同的版本！」

👉 决策：⚠️ 冲突处理
   有 3 种解决方式（你在设置里可以选）：

   方式 1 - 最新优先（推荐）：
     比较修改时间，保留更新的版本
     例：iPad 改于 14:00，电脑改于 13:30
     → 保留 iPad 的版本

   方式 2 - 本地优先：
     电脑上这个版本被保留
     iPad 上的版本被覆盖
     但会有冲突提示，你可以手动对比和合并

   方式 3 - 云端优先：
     iPad 上传的版本被保留
     电脑上的版本被覆盖

   ⚠️ **重要**：不论选择哪种方式，被覆盖的内容都会丢失
   建议操作流程：
   1️⃣ 点击同步时，如果提示有冲突
   2️⃣ 不要立即覆盖，先手动检查两个版本
   3️⃣ 复制需要的内容
   4️⃣ 再点击同步确认冲突处理

   💡 最佳实践：避免冲突比处理冲突更重要！
      建议：编辑前先同步 → 编辑后立即同步
```

---

#### **规则 5️⃣：本地有 + 云端无 + 上次同步有**

**含义**：这个便签以前在云端有，现在没了（被删了）

```
上次同步：便签 "购物清单" 存在，内容是 "..."
         ↓
你的电脑上：还有 "购物清单"

   就把电脑上这个便签也删除
   这样所有设备都同步了

   ⚠️ 删除是永久的，无法撤销！
```

---

#### **规则 6️⃣：本地有 + 云端无 + 上次同步无**

**含义**：这是你电脑上新建的便签，云端从来没有过

```

你在电脑新建：便签 "临时笔记"

云端：没有 "临时笔记"
     (因为还没同步过)

iPad：也没有 "临时笔记"
     (因为还没从云端下载)

👉 决策：⬆️ 上传新文件

   这样 iPad 下次同步就能看到了
```

---

#### **规则 7️⃣：本地无 + 云端有 + 上次同步有**

**含义**：这个便签以前在本地有，现在没了（被你删了）

```
上次同步：便签 "已完成的任务" 存在

你在电脑删除：删除了 "已完成的任务"

云端现在：还有 "已完成的任务"
        (因为删除还没同步)

iPad上：也还有 "已完成的任务"
      (还没收到删除通知)

   既然你在电脑删除了，
   就把云端的 "已完成的任务" 也删除
   同时通知其他设备也要删除
   这样所有地方都同步成"删除"状态
```

**含义**：这是云端新建的便签，本地没有（别人在另一设备新建的）

你的电脑上：没有这个便签

## 常见场景

### 场景 1：新设备加入

1. 在新设备上安装应用
2. 配置相同的 WebDAV 账号
3. 点击 **立即同步**
4. 云端数据自动下载到本地

### 场景 2：多设备编辑同一便签

**情况 A：先后编辑（无冲突）**

1. 设备 A 编辑便签，同步
2. 设备 B 同步，获取最新版本
3. 设备 B 编辑，同步
4. 设备 A 同步，获取最新版本

**情况 B：同时编辑（有冲突）**

1. 设备 A 和 B 同时编辑同一便签
2. 设备 A 先同步成功
3. 设备 B 同步时检测到冲突
4. 根据冲突策略自动解决

### 场景 3：删除便签

1. 在设备 A 删除一个便签
2. 设备 A 同步 → 云端该便签被删除
3. 设备 B 同步 → 本地该便签被删除

> ⚠️ **注意**：删除是双向传播的，一旦同步无法撤销！

### 场景 4：网络中断和恢复

**情况 A：同步中断**

```
1. 同步到 50% 时网络断开
2. 应用会自动重试（3 次）
3. 如果 3 次都失败，会显示"同步失败"
4. 已上传的文件会保留在云端
5. 重新点击同步会从断点继续
   （不会重新上传已成功的文件）
```

**情况 B：长期离线**

```
1. 在电脑上编辑：便签 A（离线状态）
2. 在 iPad 上编辑：便签 A（离线状态）
3. 电脑连网后同步 → 电脑版本上传到云端
4. iPad 连网后同步 → 检测到冲突，按冲突策略处理
   💡 所以先同步的设备版本会"赢"
```

### 场景 5：首次同步的特殊说明

**情况 A：全新账号（云端空）**

```
电脑：有 5 个便签
云端：空
iPad：未配置同步

👉 电脑同步 → 5 个便签上传到云端
👉 iPad 配置后同步 → 下载 5 个便签
```

**情况 B：迁移（云端有数据）**

```
电脑上：有旧数据（之前从未同步）
云端：有新数据（iPad 之前同步过）

👉 电脑同步 →
   - 云端新数据下载到电脑（iPad 的）
   - 电脑新数据上传到云端
   - 如有同名便签 → 冲突处理

⚠️ 重要：首次同步 5-10 分钟内不要重复同步
```

### 场景 6：恢复误删数据

如果误删了数据并已同步：

1. 进入数据目录（设置 → 数据管理 → 打开数据目录）
2. 查看 `backups/` 文件夹是否有自动备份
3. 检查 `.sync/` 文件夹中的历史版本（如果有保留）
4. 手动恢复需要的文件到 `notes/` 或 `ai-conversations/`
5. 重启应用，索引会自动重建

## 索引重建说明

### 什么是索引？

索引是本地缓存，包含：

- `notes.index.json` - 所有便签的列表和元数据
- `ai-conversations.index.json` - AI 对话的列表和元数据

索引 **不会同步** 到云端，只存在于本地。

### 索引何时重建？

| 场景       | 触发方式                           |
| ---------- | ---------------------------------- |
| 应用启动   | 自动检测索引是否过期，如过期则重建 |
| 同步完成后 | 自动重建索引（确保和云端数据一致） |
| 手动操作   | 用户点击"重建索引"按钮（如果有）   |

### 索引过期的症状

如果索引损坏或过期，你会看到：

- ❌ 便签列表显示不完整
- ❌ 便签数量不对
- ❌ 同步后数据没有更新

**解决方法**：重启应用，索引会自动重建

### 为什么索引不同步？

如果索引参与同步，会有严重问题：

```
设备 A：手动改了便签内容 → 索引也改了
       同步上传：便签内容 + 索引

设备 B：还没同步
       收到设备 A 的索引 → 索引更新了
       但便签内容还没下载？

❌ 结果：索引和实际内容不一致！
```

所以索引必须 **本地独立维护**，不参与同步。

## 冲突策略

在 **设置 → 数据同步 → 冲突策略** 中配置：

| 策略                     | 说明                         | 适用场景       |
| ------------------------ | ---------------------------- | -------------- |
| **保留最新修改**（推荐） | 比较修改时间，保留更新的版本 | 大多数场景     |
| **本地优先**             | 冲突时始终保留本地版本       | 信任本地设备   |
| **远程优先**             | 冲突时始终保留云端版本       | 云端为权威数据 |

### 🆕 冲突版本自动备份

当发生冲突时，被覆盖的版本会自动保存为备份文件：

```
原文件：notes/abc.json
冲突时：保留云端版本

备份文件：notes/abc.conflict-2025-12-04T10-30-00.json
         ↑ 这是被覆盖的本地版本

💡 这样你可以随时查看和恢复被覆盖的内容！
```

**备份文件位置**：与原文件同目录，文件名包含 `.conflict-` 和时间戳

**注意**：

- 备份文件不会同步到云端（仅本地保留）
- 如需恢复，手动重命名备份文件即可

## 同步范围

### 会同步的内容

| 类型       | 文件路径                  | 说明             |
| ---------- | ------------------------- | ---------------- |
| 文件夹配置 | `folders.json`            | 文件夹列表和属性 |
| 便签       | `notes/*.json`            | 所有便签内容     |
| AI 对话    | `ai-conversations/*.json` | 所有 AI 对话     |

**重要说明**：

- ✅ **文件夹的删除会同步** - 删除文件夹会同步到其他设备
- ✅ **便签的删除会同步** - 删除便签会同步到其他设备
- ✅ **AI 对话的删除会同步** - 删除会同步到其他设备
- ⚠️ **文件夹的顺序不同步** - 左边栏的排序顺序仅本地保存

### 不会同步的内容

| 类型     | 说明             | 原因                     |
| -------- | ---------------- | ------------------------ |
| 应用配置 | 主题、窗口大小等 | 设备相关的 UI 配置       |
| 同步配置 | WebDAV 账号密码  | 安全考虑                 |
| 索引文件 | `*.index.json`   | 本地缓存，启动时自动重建 |
| 临时文件 | `temp/` 目录     | 临时数据                 |
| 备份文件 | `backups/` 目录  | 本地备份                 |

## 故障排除

### 问题：同步后数据没有更新

**可能原因**：

1. 索引未正确重建
2. 缓存未刷新

**解决方法**：

1. 重启应用（会自动重建索引）
2. 或再次点击同步

### 问题：同步后本地数据被删除

**原因**：云端该文件已被其他设备删除

**预防措施**：

1. 定期备份（设置 → 数据管理 → 创建备份）
2. 重要便签删除前三思

### 问题：冲突频繁发生

**原因**：多设备同时编辑

**解决方法**：

1. 编辑前先同步获取最新版本
2. 编辑后立即同步
3. 避免同时在多设备编辑同一便签

### 问题：无法连接 WebDAV

**排查步骤**：

1. 检查网络连接
2. 确认 WebDAV 地址正确
3. 坚果云用户请使用"应用密码"而非登录密码
4. 检查服务器是否支持 WebDAV

### 🆕 问题：同步失败但部分文件已上传

**原因**：网络中断导致同步不完整

**系统处理方式**：

```
1. 每个文件操作都有重试机制（默认 3 次）
2. 重试间隔采用指数退避：1秒 → 2秒 → 4秒
3. 单个文件失败不影响其他文件
4. 同步完成后会保存已成功的状态
```

**你需要做的**：

1. 检查网络连接
2. 再次点击同步（会从断点继续）
3. 如多次失败，查看同步日志排查问题

## 🆕 同步日志

每次同步都会生成详细日志，用于排查问题。

### 日志位置

```
data-v1/.sync-logs/
  └── sync-2025-12-04T10-30-00.json  ← 按时间命名
```

### 日志内容示例

```json
[
  {
    "timestamp": 1733300000000,
    "level": "info",
    "action": "sync",
    "message": "开始同步，策略: newest"
  },
  {
    "timestamp": 1733300001000,
    "level": "info",
    "action": "upload",
    "path": "notes/abc.json",
    "message": "上传成功"
  },
  {
    "timestamp": 1733300002000,
    "level": "warn",
    "action": "conflict-backup",
    "path": "notes/abc.conflict-2025-12-04.json",
    "message": "冲突备份已创建"
  }
]
```

### 日志级别

| 级别    | 含义           | 示例               |
| ------- | -------------- | ------------------ |
| `info`  | 正常操作       | 上传成功、下载成功 |
| `warn`  | 警告（可恢复） | 重试中、冲突备份   |
| `error` | 错误（需关注） | 文件操作失败       |
| `debug` | 调试信息       | 详细的内部状态     |

### 自动清理

- 只保留最近 **10 次** 同步的日志
- 旧日志自动删除

## 技术细节

### 同步流程

```
1. 连接服务器（带重试）
2. 扫描本地文件
3. 获取云端清单
4. 验证清单一致性 🆕
5. 三方比较计算差异
6. 执行同步操作（带重试 + 冲突备份 🆕）
7. 更新云端清单（带重试 🆕）
8. 更新本地状态
9. 保存同步日志 🆕
10. 重建索引
11. 刷新界面
```

### 🆕 manifest 一致性验证

同步前会验证云端清单与实际文件是否一致：

```
问题场景：
  manifest.json 记录有 notes/abc.json
  但实际文件已被手动删除（如通过 WebDAV 客户端）

解决方案：
  1. 采样检查文件存在性（最多 10 个）
  2. 如发现不一致，自动从 manifest 移除
  3. 避免"删除不存在的文件"等无效操作
```

### 文件哈希

使用 MD5 计算文件内容哈希：

- JSON 文件会先规范化（排序 keys）再计算
- 确保相同内容产生相同哈希

### 原子写入

写入文件时采用原子操作：

1. 先写入临时文件
2. 成功后重命名为目标文件
3. 防止写入中断导致数据损坏

## 最佳实践

### 日常使用

1. **定期同步**

   ```
   编辑前：点击同步 → 确保有最新版本
   编辑后：编辑完成 → 立即点击同步
   ```

2. **避免冲突**

   ```
   ✅ 推荐：A 编辑→同步，B 编辑→同步（串行）
   ❌ 避免：A 和 B 同时编辑同一便签（并行）
   ```

3. **重要数据备份**

   ```
   定期导出：设置 → 数据管理 → 创建备份
   推荐频率：每周一次
   ```

4. **网络不稳定时的操作**
   ```
   ❌ 不要：网络不稳定时关闭应用
   ✅ 应该：
      1. 继续点击同步
      2. 应用会自动重试 3 次
      3. 如果仍失败，稍后再试
   ```

### 多设备协作

**3 台设备的同步场景**

```
电脑、iPad、手机都在用

✅ 规范做法：
   电脑：07:00 编辑和同步
   iPad：08:00 同步→编辑→同步
   手机：09:00 同步→编辑→同步

❌ 问题做法：
   电脑：07:00 编辑（未同步）
   iPad：08:00 编辑（未同步）
   手机：09:00 编辑（未同步）
   三个版本冲突 → 只能保留一个
```

**冲突频繁时的调试**

```
1. 查看设备时间是否同步
   （时间不同导致"最新优先"判断错误）

2. 查看是否有网络延迟
   （网络慢可能导致同步状态记录不准确）

3. 如果频繁冲突，改用"本地优先"或"云端优先"
   （避免复杂的时间判断）
```

### 故障恢复

**如果怀疑数据被污染**

```
1. 不要再同步！
2. 进入数据目录
3. 备份整个 data-v1 文件夹（防止数据丢失）
4. 检查 .sync/manifest.json 中的文件列表
5. 对比 notes/ 和 ai-conversations/ 中的实际文件
6. 如果有多余文件或缺失，手动调整
7. 删除 sync-state.json
8. 重启应用强制重建索引
9. 再次同步
```

**如果某个便签反复冲突**

```
1. 暂停编辑该便签
2. 全部设备都同步一遍（确保状态一致）
3. 只在一台设备上编辑该便签
4. 其他设备定期同步获取更新
```
