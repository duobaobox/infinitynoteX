## 2️⃣ 组件解耦策略深度分析

### 2.1 Feature-based 架构解析

项目采用了**功能驱动架构 (Feature-based Architecture)**，这是现代前端最佳实践之一：

```

│   │   ├── Sidebar.css
│   │   └── index.ts

│   │   ├── ListPanel.tsx           # 路由容器
│   │   └── ListPanel.css
│   ├── EditorPanel/                # 编辑器面板模块
│   │   ├── index.tsx
│   │   └── AITab.tsx               # ⚠️ 应移至 ai-chat/
│   └── ToolPanel/                  # 工具面板模块
│
├── 📁 note/                        # 便签功能域
│   ├── views/
│   │   ├── NoteEditor/             # 便签编辑器
│   │   │   ├── NoteEditor.tsx      # 容器组件

    ├── views/
    │   └── ConversationList/       # 对话列表
    └── index.ts
```

#### ✅ 优点

1. **高内聚低耦合**：每个 feature 封装完整的业务逻辑
2. **易于定位**：按业务领域组织，新人上手快
3. **独立演进**：各 feature 可独立开发和测试
4. **符合 DDD 思想**：领域边界清晰

#### ⚠️ 问题点

| 问题                 | 位置                             | 影响           | 建议                    |
| -------------------- | -------------------------------- | -------------- | ----------------------- |
| **跨 Feature 依赖**  | `AITab` 在 `layout/EditorPanel/` | 破坏模块边界   | 迁移至 `ai-chat/views/` |
| **组件重导出**       | `components/ListPanel.tsx`       | 增加理解成本   | 统一入口                |
| **Feature 内无分层** | `note/` 缺少 services            | 逻辑与视图混杂 | 增加 services 子目录    |

## 3️⃣ 状态管理架构分析

### 3.1 Store 架构现状

项目使用 **Zustand 5.0** 进行状态管理，整体设计合理但存在改进空间：

```typescript
// workspaceStore.ts - 当前结构
interface WorkspaceState {
  // ============ UI 状态 ============
  showEditor: boolean;
  showSidebar: boolean;

  // ============ 业务状态 ============
  selectedFolderId: string | null;
  selectedNoteId: string | null;
  selectedToolId: string | null;
  selectedToolItemId: string | null;
  workspaceView: WorkspaceView;

  // ============ 数据状态 ============
  folders: Folder[];
  notes: NoteIndex[];
  aiConversations: AIConversationPreview[];
  currentFolderName: string;

  // ============ 触发器 ============
  refreshListTrigger: number;
  refreshAIConversationsTrigger: number;
  resetEditorTabTrigger: number;
  isFirstLaunch: boolean | null;

  // ============ Actions (30+ 个) ============
  // ...
}
```

### 3.2 Store 问题分析

| 问题              | 严重程度 | 说明                                     |
| ----------------- | -------- | ---------------------------------------- |
| **职责过重**      | 🔴 高    | 单个 Store 管理 UI + 业务 + 数据，332 行 |
| **缺少领域模型**  | 🟡 中    | 直接使用原始数据结构                     |
| **副作用内置**    | 🟡 中    | 异步操作直接写在 Store 内                |
| **缺少 Selector** | 🟡 中    | 未优化渲染性能                           |

### 3.3 推荐的 Store 拆分方案

```
store/
├── 📁 slices/                      # 状态切片
│   ├── uiSlice.ts                  # UI 状态
│   │   └── showEditor, showSidebar, workspaceView
│   ├── folderSlice.ts              # 文件夹状态
│   │   └── folders, selectedFolderId
│   ├── noteSlice.ts                # 便签状态
│   │   └── notes, selectedNoteId
│   └── aiConversationSlice.ts      # AI 对话状态
│       └── aiConversations, selectedToolItemId
│
├── 📁 selectors/                   # 选择器
│   ├── noteSelectors.ts
│   └── folderSelectors.ts
│
├── workspaceStore.ts               # 聚合 Store
└── settingsStore.ts                # 设置 Store
```

**拆分收益：**

1. **单一职责**：每个 slice 职责明确
2. **性能优化**：通过 selectors 减少不必要渲染
3. **易于测试**：小模块更容易单元测试
4. **团队协作**：多人可并行开发不同 slice

#### TD-002: 缺少 Service 抽象层

**现状代码片段：**

```typescript
// 直接调用 window.storage，难以 mock 和测试
const loadNote = async (id: string) => {
  const note = await window.storage.getNote(id); // ❌ 直接调用
  setNoteTitle(note.title);
};
```

**推荐修复：**

```typescript
// services/noteService.ts
class NoteService {
  async getNote(id: string): Promise<Note> {
    return window.storage.getNote(id);
  }

  async updateNote(id: string, data: Partial<Note>): Promise<void> {
    await window.storage.updateNote(id, data);
    eventBus.emit('note:updated', id);
  }
}

export const noteService = new NoteService();

// 使用时
const loadNote = async (id: string) => {
  const note = await noteService.getNote(id); // ✅ 通过 Service 调用
  setNoteTitle(note.title);
};
```

#### TD-005: 自动保存逻辑重复

**重复位置：**

- `NoteEditor.tsx` (L88-108)
- `FloatingNoteWindow.tsx` (L76-98)

**推荐修复：**

```typescript
// hooks/useAutoSave.ts
export function useAutoSave<T>(saveFunc: (data: T) => Promise<void>, delay = 800) {
  const timerRef = useRef<NodeJS.Timeout | null>(null);

  const trigger = useCallback(
    (data: T) => {
      if (timerRef.current) clearTimeout(timerRef.current);
      timerRef.current = setTimeout(() => saveFunc(data), delay);
    },
    [saveFunc, delay],
  );

  useEffect(() => {
    return () => {
      if (timerRef.current) clearTimeout(timerRef.current);
    };
  }, []);

  return { trigger };
}

// 使用时
const { trigger: saveNote } = useAutoSave((data) => noteService.updateNote(noteId, data), 800);
```
